# Proposals (fable_5): make NCM's codes predictable from the prefix

Grounding beyond the brief (read from the code and run logs, not re-run):
- Blind-guess entropy per level (`ncm-l7/plan-probe.json`): 8.2, 9.5, 10.8, 10.7, 10.2, 10.6, 10.1 bits/code.
  Every level uses its 2,048 codes almost uniformly; the 236 codes carry ~2,430 bits of marginal entropy for a
  64-token chunk whose text has a few hundred. The levels are massively redundant with each other, and the
  generator recovers only part of that redundancy (1,190 bits teacher-forced).
- Residual structure (`upstream/ncm/models/quant.py`, `forward`/`z_to_idx`): level k quantizes
  `z_rest = z - sum_{i<k} quantized_i`, i.e. the *quantization error* of the coarser levels. Every residual is
  built from `z.detach()`, so no gradient from anything computed on levels >= 1 reaches the encoder.
- Generator head (`code_scale/models.py` -> `shared_output_head: True`): one `nn.Linear(384, 2048)` shared by
  7 unrelated codebooks (per-level bias only). Upstream also has `tie_heads_to_codebook` (logits =
  -||proj(h) - E_c||^2, zero extra params) which is not used.
- Decoder is trained with `fine_drop` (prob 0.5, min_keep 1): it already reconstructs from any truncated
  prefix of levels, so it is tolerant to the fine levels' exact content.
- Mixed forcing (`diag-l7/report.json`): true levels 0-3 -> 0.675 similarity, 0-4 -> 0.825, 0-5 -> 0.947.

Reading of facts 4-7 that all three proposals rest on:
1. **Fine levels (3-6, ~940 of the 1,190 bits) are unpredictable for a *parameterization* reason.** In a
   residual quantizer the level-k code is the index of the nearest codebook vector to the coarser levels'
   quantization error. That error is, by construction, close to uniform inside the coarser Voronoi cell: it is
   noise with respect to the content. Knowing the content roughly (prefix) or exactly at the neighbouring
   positions (fact 5) tells you nothing about which of 2,048 noise directions this cell's error points to. That
   is why reveals removed 0.6% and why levels 4-6 cost 697 bits even though, given true levels 0-3, the text has
   far less than 250 bits left. The code is a *determined* function of the text, but a hash a 13M generator
   cannot compute.
2. **Coarse levels (0-2, ~250 bits) are unpredictable for an *information-theoretic* reason.** An 11-bit
   summary of a 16-token segment with ~60 bits of prefix-conditional uncertainty is close to uniform unless the
   partition is deliberately aligned with the predictable attributes of the segment. k-means on pooled
   encoder features is not aligned with anything, and absolute position embeddings make it shift-unstable
   (fact 6). Path A's InfoNCE nudged exactly this alignment at level 0 and won 1 bit of 8 - 4 bits of 940.
   No coarse-level-only fix can pass the 30% test; the fine levels must be fixed first (P1), and the coarse
   partition aligned second (P2).

### P1. Gaussian pyramid instead of Laplacian: non-residual multiscale VQ (fine codes quantize content, not quantization noise)
- Atoms used: 269 (multi-granularity / hierarchical pooling, row 15), 185 (bidirectional context, rows 2/7/10/11/15/19), 102 (tokenization that respects structural boundaries, rows 3/10/17), 50 (latent geometry that captures invariants, rows 5/18). Mostly the "hierarchical feature pooling" atom: the current tokenizer is a Laplacian pyramid (each level = detail after subtracting the coarser reconstruction); a Gaussian pyramid (each level = the content itself at that resolution) is the alternative the atom points at.
- Mechanism: Change what level k quantizes from `down_k(z - sum_{i<k} q_i)` (noise) to `down_k(z)` (pooled content). Then code_k[j] = Q_k(mean of the encoder features under position j at scale k). This is a smooth function of the *content* under that window, with a codebook whose vectors live in content space. Given the prefix and the coarser levels (which now are blurrier versions of the same map, i.e. an actual prediction of this level), the generator has to predict "which content cluster is at this window", the way a token model predicts which token comes next. Uncertainty in the text spreads probability over *neighbouring* content codes instead of over 2,048 arbitrary noise directions. Facts: attacks fact 5/fact 4 directly (the 697 bits at levels 4-6 are the noise cost); level 0, which already is a non-residual code, is the one level this does not help, and indeed its 33 bits are not the problem. Fact 6 (shift instability) is untouched by P1 and is noted as the first follow-up (drop `enc_positional`, add `enc_attn_window=8`; both are existing flags in `vae.py`).
- Exact change (all in `upstream/ncm/models/quant.py`, mirrored in `forward`, `z_to_idx`, `idx_to_zhats`, `idx_to_ncm_input`, `idx_to_z_q`, `get_next_autoregressive_input`; gate it behind a `residual: false` key in `vector_quantizer_config` so the old path stays):
  1. Never subtract: `flat_input_BLC = self._down_for_quant(z_no_grad, i, level)` for every level (drop the `z_rest -= quantized` line).
  2. Accumulate as a running *mean* over levels, not a sum, so `z_hat` keeps the scale of `z` after any truncation: `z_hat = (z_hat * i + quantized) / (i + 1)`. `fine_drop` and the losses (`mse(z_hat, z)` per level, commitment, final STE `z = z + (z_hat - z).detach()`) are unchanged.
  3. Levels 5 and 6 both have 64 positions and would quantize the same vector. Make them product-quantization halves: level 5 quantizes `z[..., :128]`, level 6 quantizes `z[..., 128:]`, each with its own 2,048 x 128 codebook; `quantized` is the 256-d vector with the other half zero before `_apply_quant_resi`. (22 bits per token position of exact-identity capacity; the decoder has 2 blocks to combine them.) Levels 0-4 stay at [4, 8, 16, 32, 48] with 256-d codebooks.
  4. `code_scale/models.py`: `build_codec` passes `residual: False`; nothing changes in `build_ncm` for the first run. `idx_to_ncm_input` already feeds the generator the cumulative `z_hat` pooled to the next level's size; with means this is a bona fide prediction of the next level.
  Optional second run (zero extra params): `tie_heads_to_codebook: True` instead of `shared_output_head` in `build_ncm`, because in P1 the codebook geometry *is* the content geometry and the distance head reads it directly (the shared linear head has to learn 7 unrelated index->vector maps through one 384x2048 matrix).
- Why it's new vs "already tried": every tried item kept residual quantization and changed the generator (block_causal, reveals/MaskGIT, layouts), the codebook sizes (Path B2: smaller codebooks made the fine levels carry *more* noise, bits 1,008 but no quality), or added a loss at level 0 (Path A). None changed what the fine levels quantize, which is where 940 of the bits are.
- One-night test: train the P1 tokenizer 5,000 steps (`train.py codec --restart-fix`, ~1.3 h at 0.9 s/step); run `codec_eval` (gate) and `plan_probe --probe-only` (blind-guess entropy per level, stability). If the gate passes, train NCM 1,800 steps (~2.5 h), then `reveal_bits`-style teacher-forced bits per level against AR's 250.5 (reuse `plan_probe --gain-only`, which already prints `ncm_total_bits_per_chunk`). Expected: levels 0-2 roughly unchanged (~250 bits; the blind-guess entropy may even drop because frequent content gives frequent codes), level 3 ~200, level 4 ~150, levels 5-6 ~100 each given a near-token-resolution level 4 -> **~800 bits, extra ~550 (pass <= 660)**. Pass line as in the brief; also report blind-guess entropy per level (expected to fall well below 10 bits at fine levels, which is the signature that codes became content-like).
- Cheat risk: the only way P1 lowers bits by losing information is codebook under-use at the fine levels (EMA k-means on redundant content maps can collapse: a few giant clusters). That shows up as the reconstruction gate failing (99% / 50%) and in `codes_used_l0_l2`/per-level usage; the restart fix is on. If PQ halves fail to reach 99% tokens, the fallback is one residual step at the finest scale only (level 6 = Q(z - up(Q5))), accepting ~250 noise bits at level 6, or FSQ (no collapse) at the fine levels.
- Confidence it passes the 30% test: **35%**. The argument is clean for levels 4-6; the risk is that levels 3-4 (pooled pairs of tokens) stay hashes because any 11-bit partition of a 2-token window is nearly uniform given the prefix, which would leave the total near 900 rather than 800.
- GPU cost on a Quadro T1000: ~4.5 h (1.3 h codec + 2.5 h NCM + 0.5 h measurements); +2.5 h for the tied-head rerun if the first lands in 660-800.

### P2. Rate-distortion tokenizer: a prefix-conditioned entropy model on all levels, with a soft-assignment gradient path into the encoder
- Atoms used: 188 (Gumbel-Softmax / STE / soft relaxations, rows 2/14), 60 (continuous relaxation of discrete choices, rows 9/14), 33 (composite loss with secondary penalties, rows 3/20), 59 (perplexity as the signal, rows 11/13/20). The combination says: make the quantity you care about (code perplexity under a conditional model) a differentiable training term.
- Mechanism: The test metric is -log q(codes | prefix, coarser codes). Add exactly that as a loss on the tokenizer, computed by a small jointly-trained rate model R, and let it reach the encoder at *every* level through a soft assignment over the near-tie codes. The encoder then has two legal ways to lower the rate without losing information: (a) within each level's near-tie set, move the latent toward the code the rate model expects (the differentiable twin of P3's search); (b) reshape the partition so coarse codes follow prefix-predictable attributes rather than hashing identifiers (the alignment missing per reading 2 above). Reconstruction loss holds the information in place. This is the standard learned-compression recipe (rate term from a learned entropy model, distortion term), which Path A approximated with a contrastive latent term at one level.
- Exact change:
  1. `quant.py`: add a method `soft_rate_inputs(z)` that re-runs the level loop with `z` *not* detached in the residual: `r_k = down_k(z - sum_{i<k} quantized_i.detach())` (one line difference from `forward`; in a P1 tokenizer it is just `down_k(z)`), returns per level `d2_k = ||r_k - E_k||^2` (E detached; the EMA codebook update is untouched) and the hard indices.
  2. `code_scale/plan_loss.py`: `RateModel`: per level k, input = [AR prefix features (768-d, frozen, as in Path A; fairness caveat as before) -> 256] + the position's generator input vector from `idx_to_ncm_input` of the *hard* coarser codes (detached, 256-d; for level 0 the learned query is replaced by zeros) + level/position embedding -> 2-layer MLP (512) -> 256 -> logits by the distance form against E_k (detached). Soft posterior `p_k = softmax(-d2_k / tau_k)` restricted to the 16 nearest codes, `tau_k` = EMA of the gap between the nearest and second-nearest distance at that level (so the softness covers near-ties only). Loss `rate_k = sum_pos sum_c p_k(c) * (-log R(c))` in bits; total `rec + vq_loss + lambda * sum_k rate_k / 236`. Gradient to the encoder via `d2_k`, to R via `log R`. Ramp lambda from 0 over the first 1,000 steps (codebooks must settle first). Two lambdas: 0.1 and 0.3.
  3. `train.py codec --rate-weight L --plan-batch 32` reusing the Path A window/AR-feature path (1.2 s per 64 prefixes; use 32 of the 64 windows for the rate term as Path A did).
  Decision measurement needs no NCM run: R itself is a prefix-conditioned code model, so its held-out teacher-forced bits per chunk (2,048 windows, same protocol as `reveal_bits.py`) are the first-night number; a passing tokenizer then gets the real NCM on night 2.
- Why it's new vs "already tried": Path A was InfoNCE on the *level-0 latent* only (4 of 236 codes; it could at most have moved 33 bits), with no gradient path to levels >= 1 (noted in `docs/ncm-next-plan.md`, Path B section). P2 puts the measured quantity itself on all 236 codes and builds the missing gradient path; the soft near-tie posterior is what makes that possible without touching the hard EMA codebook.
- One-night test: lambda 0.1 and 0.3, 5,000 steps each on the current RVQ tokenizer (~2.3 h each at ~1.6 s/step; run 0.3 first, 0.1 only if 0.3 fails the gate). Gate on `codec_eval`; bits = R's held-out teacher-forced bits (per level, total). Pass line: R's bits <= 910 (extra <= 660) with the gate intact. Expected on RVQ: 1,190 -> ~900-1,000 (the near-tie room exists in 256-d, but noise residuals limit (a) and the coarse alignment (b) is worth ~100-150 bits); on top of a passing P1 tokenizer: a further 100-200 bits, and this is where the coarse levels' 250 bits can move.
- Cheat risk: (i) the encoder shrinks fine residuals toward a default code and loses tokens -> gate. (ii) R overfits training windows -> bits are measured on held-out windows. (iii) R borrows the frozen AR's prefix reading -> flagged as in Path A; the night-2 NCM run with its own prefix is the number that counts for the step-6 decision. (iv) tau too large makes the soft posterior cover far codes, so the encoder can "lower rate" by moving latents far -> reconstruction loss pushes back, and tau is tied to the nearest-gap so it cannot.
- Confidence it passes the 30% test: **30%** alone (the residual-noise ceiling of reading 1 stays), ~50% as the second night on a P1 tokenizer that already lands in 660-800.
- GPU cost on a Quadro T1000: ~2.5 h per lambda for the decision (one lambda typically), +2.5 h NCM on night 2.

### P3. Propose-and-verify encoding: the generator drafts among near-tie codes, the decoder verifies exact reconstruction (rate-distortion optimized quantization)
- Atoms used: 139 (speculative decoding: cheap drafter proposes, authoritative model verifies, output distribution preserved; appears in rows 4/5/6/8/16), 57 (constrained decoding via logit masking over admissible candidates, rows 1/12), 61 (inference-time decoding interventions, rows 9/16). The mapping: the *generator* is the drafter of codes from the prefix, the *tokenizer's decoder* is the verifier (exact token reconstruction), and the admissible set is the top-m nearest codes.
- Mechanism: The code space is hugely redundant (2,430 bits of marginal entropy for a few hundred bits of text), and in 256-d the nearest and the 8th-nearest codebook vector for a noise-like residual are at nearly the same distance, while the `fine_drop`-trained decoder is tolerant to the fine levels' exact content. So for many positions several codes reconstruct the chunk identically. Argmin picks one arbitrarily (the hash); picking instead the candidate the generator assigns the highest probability turns those positions into (nearly) free bits, and training the generator on the chosen codes sharpens it further (an EM loop on the achievable code length). The decoded text is verified exact, so the measured -log q is a true code length for the text. Fact 5 is consistent: among near-ties, neighbours' codes don't tell you which one argmin picked, but *we* get to pick.
- Exact change (`code_scale/models.py`, no tokenizer retraining):
  1. `rdoq_encode(codec, ncm, prefix, chunk, levels=(5, 6), m=8, beta=1.0)`: run `z_to_idx` level by level (expose a per-level step: distances already exist in `quant.py`). For a level in `levels`, take the m nearest codes per position; get the generator's log-probs for that level teacher-forced on the codes chosen so far (one forward per RDOQ level, `ncm_logits` with `corrupt_rate=0`); score `s_c = log q(c) - beta * (d2_c - d2_min) / sigma_k` (sigma_k = running std of nearest distances at level k; beta=0 is the pure "any near-tie is fine" variant), pick the max, recompute the residual with the chosen code, continue.
  2. Verify: `codec.decode(chosen).argmax(-1)` must equal `codec.decode(argmin_codes).argmax(-1)` on every position (no new reconstruction errors); otherwise fall back to the argmin codes for that chunk. Log acceptance rate per level.
  3. `train.py ncm --rdoq 5,6`: targets = the verified chosen codes each step (3 forwards per step instead of 1: levels 5 and 6 plus the training pass). Optionally fine-tune the decoder (encoder frozen) on chosen codes for 500 steps to raise acceptance.
  4. Measurement: held-out bits = -log q over the final (chosen or fallen-back) codes, 2,048 windows; gate = `codec_eval` on the chosen codes; acceptance rate.
- Why it's new vs "already tried": every previous run fed the generator argmin codes and asked it to predict them better (attention pattern, reveals, codebook size). P3 changes which codes are the target, exploiting the redundancy the brief measured, and keeps the information by verification. Smaller codebooks (B2) removed codes globally and lost information (quality fell to 0); P3 removes bits only where reconstruction is provably unchanged.
- One-night test: **pre-test first (20 min, no training):** with the existing `codec-l7` + `ncm-l7` (or `ncm-rv7`), run `rdoq_encode` on 2,048 held-out windows at levels 5-6 with m=8, beta in {0, 1}: report one-shot bits (expected to fall from 1,191 by 60-150 just from picking the generator's favourite among near-ties), acceptance rate (expect > 60% of chunks exact-equal), and the gate. If the one-shot gain is < 40 bits or acceptance < 30%, skip the night. **Night:** NCM 1,200 steps with `--rdoq 5,6` (~5 h at 3 forwards/step), then the measurement. Expected after EM: levels 5-6 from 412 to ~150-200 bits -> **total ~930-980, extra ~680-730**; borderline, which is why levels 3-4 (531 bits, two more forwards) are the follow-up if the pre-test is strong.
- Cheat risk: (i) the loop could prefer codes that decode "the same" only on the 64 tokens while the gate is measured on the same 64 tokens -> that is the definition of information kept here; the gate is identical to the brief's. (ii) The generator trained on its own picks becomes confident about them -> fine, the code length is still valid because every accepted chunk decodes exactly; fallback chunks are scored with their argmin codes. (iii) beta=0 with m large would drift latents to codes far from the residual and harm the *quality* of z_hat for downstream uses even though tokens match -> keep m=8 and report the mean distance ratio of chosen vs nearest.
- Confidence it passes the 30% test: **30%** on levels 5-6 alone (needs ~280 of the 412 bits; the pre-test tells within 20 minutes whether that is plausible), ~45% if extended to levels 3-6 on a second night.
- GPU cost on a Quadro T1000: 0.3 h pre-test; ~5.5 h for the night (1,200 NCM steps at 3x cost + measurement).

## Considered and rejected (so they are not re-proposed)
- **Prefix-conditioned decoder (codes = innovation only).** Makes NCM's bits drop toward AR's trivially because the decoder becomes the language model; codes become *less* predictable, the generator learns nothing, and quality is the 2-block decoder's. Opposite of the brief's goal, even though it would pass the bits number.
- **Drop levels 5-6 / shrink fine codebooks.** Pure information removal unless the gate still passes, and Path B2 showed bits fall with no quality. Worth 20 minutes as a *control* for P3 (`reconstruct_multiscales` on 1,024 chunks: if levels 0-4 alone give >= 99% tokens, P3's acceptance will be near 100% and the fine levels were already free).
- **Structural skeleton as the coarse code** (atoms 253 AST / 45 edit-template / 57 FSM, rows 1/8/12): aux head forcing levels 0-1 to encode a 16-class token skeleton with capped codebooks. Principled alignment of the coarse partition with the most predictable attribute of code, but it can move at most ~100 of the 940 bits (coarse levels hold 250 and the skeleton of 64 future tokens is itself ~70-80 bits uncertain), and it pushes identifier information into the fine levels, which under RVQ are noise. Only sensible as P2's supervised variant on a P1 tokenizer.
- **InfoNCE on more levels.** No gradient path (`z.detach()` residuals); P2 supersedes it.
- **Shift-equivariant encoder alone** (`enc_positional=False`, `enc_attn_window`): fixes fact 6 but not reading 1; it is the first flag flip after P1 passes the gate, not a standalone night.

## Summary
1. P1 Gaussian pyramid (non-residual multiscale VQ, PQ halves at the finest scale): 35%. Primary; attacks the 697 fine-level bits at their cause.
2. P2 Rate-distortion training with a soft near-tie posterior and an all-level entropy model: 30% alone, ~50% stacked on P1.
3. P3 Propose-and-verify (RDOQ) encoding with a 20-minute pre-test on existing checkpoints: 30%, cheapest to falsify.
4. Alien combos: the speculative-decoding atom (139), present in six rows, genuinely produced P3 (drafter = generator, verifier = decoder); the relaxation atoms (188/60) made P2's gradient path concrete; P1 came from reading the quantizer and would have been had anyway - the "hierarchical pooling" atom (269) only named it.
5. Nothing in the 20 rows addressed the central finding directly (residual codes are quantization noise); the rows are strongest as mechanism libraries for a hypothesis the brief's facts already point to.
